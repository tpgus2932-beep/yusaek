# 일반사유로변경 시 템플릿 문자 동시 발송

## 배경

`docs/superpowers/specs/2026-07-24-returns-seller-reason-change-and-sms-design.md`에서
구현한 "일반사유로변경" 버튼은 사유변경만 처리한다. 실제 운영에서는 사유를 바꾸는
동시에 해당 구매자에게 안내 문자도 보내야 하는데, 지금은 버튼을 누르면 바로
처리가 진행돼서 문자를 별도로 보낼 방법이 없다.

## 목표

"일반사유로변경 (N건 선택)" 버튼을 누르면:
1. 먼저 SMS 템플릿 선택 모달이 뜬다 (기존 `/sms/templates`의 템플릿 목록).
2. 템플릿을 고르고 "진행"을 누르면: ① 기존 `/returns/ably-change-reason-submit`으로
   사유변경을 처리하고, ② 선택된 각 건의 `buyer_tel`로 그 템플릿 문구를
   `/return-automation/reply-sms`를 통해 개별 발송한다.
3. 완료 후 "사유변경 X/N건 성공, 문자전송 Y/Z건 성공" 형태로 결과를 보여준다.

## 비범위

- 템플릿 문구의 변수치환(상품명/이름 등 자동 삽입) — 템플릿 원문 그대로 전송.
- 새 백엔드 엔드포인트 — 기존 `/sms/templates`(목록 조회), `/return-automation/reply-sms`
  (개별 발송)만 재사용.
- 판매자대기 탭의 다른 버튼(에이블리 환불 요청, 이지어드민 입고처리 등)에는
  영향 없음 — 이 변경은 "일반사유로변경" 버튼에만 적용.

## 동작 상세

- 버튼 클릭 시 사유변경 API를 바로 호출하지 않고, 클릭 시점의 선택 항목을
  보관해둔 채 템플릿 모달을 연다. 모달이 열리면 `/sms/templates`를 호출해
  템플릿 목록(`{id, name, msg, title, msgType}`)을 불러오고, 드롭다운으로
  이름을 보여주며 선택된 템플릿의 `msg`를 미리보기로 표시한다.
- "진행" 클릭 시:
  1. `/returns/ably-change-reason-submit`을 기존과 동일하게 호출 (선택된 items
     전체를 한 번에 전송, 결과로 성공/실패 건수와 큐 갱신).
  2. 그 응답을 받은 뒤, 클릭 시점에 보관해둔 선택 항목들을 순회하며, `buyer_tel`이
     있는 건만 `/return-automation/reply-sms`에 `{phone: item.buyer_tel, msg: 선택한
     템플릿.msg}`로 개별 POST (사유변경 성공/실패 여부와 무관하게 buyer_tel이
     있으면 문자는 시도한다 — 사용자가 이렇게 결정함).
  3. 문자 발송 도중 `need_ezdesk_session: true` 응답을 받으면 그 시점에서 나머지
     발송은 중단하고 "이지데스크 세션 만료, N건까지만 발송됨" 형태로 안내한다.
  4. 완료되면 모달을 닫고 사유변경/문자전송 결과를 하나의 메시지로 합쳐서 보여준다.
- `buyer_tel`이 빈 문자열인 건은 문자 발송 대상에서 제외하고 카운트에서도
  "제외 M건"으로 별도 표시한다.

## 테스트 계획

- 프론트엔드 로직이라 자동화 테스트 없음(이 프로젝트 프론트 컨벤션) — `npm run lint`
  통과 확인 + 실제 개발 서버에서 판매자대기 탭 1건 이상으로 수동 확인:
  템플릿 모달이 뜨는지, 진행 시 사유변경과 문자전송이 순서대로 되는지, buyer_tel
  없는 건은 문자만 스킵되는지, 이지데스크 세션 만료 시 중단 메시지가 뜨는지.
